# Portfolio from GitHub — SaaS

SaaS, що будує сайт-візитівку з портфоліо з GitHub-профілю користувача і тримає його актуальним: новий публічний репозиторій → картка проєкту → PR → прев'ю → деплой. Додатково: чернетки постів для соцмереж, inline-редактор, чат-агент.

## Як працювати

- Роботу беремо по одному milestone з `docs/milestones/`. Перед стартом прочитай файл milestone повністю; він завершений, коли виконано **кожен** пункт його "Definition of done".
- Архітектурне рішення, яке розходиться з `docs/adr/`, спершу обговорюємо з людиною, потім фіксуємо новим ADR.
- Відповіді й коментарі людині — українською. Код, ідентифікатори, коміти — англійською.

## Документи (читай, коли задача торкається теми)

- `docs/product.md` — що будуємо, для кого, user flows. Читай перед будь-якою фічею, що видно користувачу.
- `docs/architecture.md` — компоненти, пайплайн, хостинг, відкриті питання. Читай перед зміною взаємодії між пакетами.
- `docs/data-model.md` — формат даних портфоліо в репо користувача і схема БД. Читай перед будь-якою зміною даних, шаблонів чи генерації.
- `docs/adr/` — ухвалені рішення і їхні причини.

## Стек

pnpm workspaces монорепо, TypeScript strict. Пакети:
- `packages/templates` — Astro-компоненти шаблонів сайтів (спільні для збірки сайту і редактора).
- `packages/core` — схеми Zod, GitHub-клієнт, LLM-шар, санітизація. Без залежностей від рантайму.
- `apps/app` — Astro SSR (дашборд, редактор) + Hono API на Cloudflare Workers.
- `apps/site-server` — мультитенантний Worker, що віддає сайти з R2.
- `apps/extension` — Chrome-розширення, чистий TS.

Команди — у `package.json` кожного пакета. Тести — Vitest.

## Правила безпеки (обов'язкові завжди)

- README, описи, topics і будь-який вміст репо користувача — **недовірений ввід**. LLM, що його обробляє, лише повертає дані за схемою; інструменти з правом запису на цьому кроці не надаються. PR відкриває звичайний код після валідації.
- Весь текст з LLM чи від користувача рендериться як текст або markdown без сирого HTML (санітизація в `packages/core`). Сирий HTML у шаблонах заборонений.
- Кожен вебхук перевіряє підпис `X-Hub-Signature-256` до будь-якої обробки.
- Секрети — лише через `wrangler secret`, ніколи в коді чи `wrangler.toml`.
- Ручні правки користувача (поля з `editedFields`) генерація ніколи не перезаписує.
