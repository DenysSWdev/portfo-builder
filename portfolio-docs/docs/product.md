# Продукт

## Проблема

Розробники рідко оновлюють портфоліо: це ручна нудна робота, хоча вся інформація вже є на GitHub. Сайт швидко застаріває.

## Рішення

Сервіс читає GitHub-профіль і публічні репозиторії, будує сайт-візитівку за шаблоном і далі **сам підтримує його актуальним**. Те, чого немає на GitHub (про себе, контакти, соцмережі, сертифікати), користувач додає сам.

## Для кого

Розробники, яким потрібна публічна сторінка-портфоліо (пошук роботи, фриланс, особистий бренд), без бажання писати й підтримувати власний сайт.

## Ключові принципи

- **Автоматично, але під контролем.** Будь-яка зміна сайту — це PR з прев'ю. Auto-merge — опція, за замовчуванням вимкнена.
- **Дані належать користувачу.** Контент і зображення лежать у його репозиторії; хостинг наш, але дані переносні.
- **Ручна правка сильніша за генерацію.** Те, що користувач відредагував, агент більше не чіпає.
- **Тексти звучать по-людськи.** Описи й пости користувач публікує під своїм ім'ям, тож стиль — стриманий, конкретний, без маркетингових штампів і емодзі за замовчуванням.

## User flows

### 1. Онбординг
1. Логін через GitHub.
2. Сервіс створює (або користувач обирає) репозиторій даних портфоліо і встановлює на нього GitHub App.
3. Сервіс читає профіль і публічні репо, пропонує список проєктів; користувач позначає, які показувати (topic `portfolio` або галочка в дашборді — див. `architecture.md`, відкриті питання).
4. Користувач обирає шаблон, заповнює "Про себе", контакти, соцмережі.
5. Перший PR → прев'ю → публікація на `username.<домен>`.

### 2. Новий проєкт
1. Користувач робить репо публічним і додає topic `portfolio`.
2. Пайплайн генерує картку проєкту і чернетку поста.
3. Відкривається PR з прев'ю; користувач отримує посилання.
4. Merge вручну або автоматично (якщо увімкнено і всі перевірки пройдені) → продакшн.

### 3. Оновлення проєкту
- Зміна README → картка оновлюється (крім полів з `editedFields`).
- Новий GitHub Release → картка оновлюється + чернетка поста "що нового".
- Звичайні push без зміни README пост не генерують.

### 4. Inline-редагування
1. На своєму сайті користувач додає `?edit` → редирект у редактор застосунку.
2. Редактор показує той самий шаблон з редагованими полями (`contenteditable`) і кнопками заміни зображень.
3. Зміни видно одразу. "Зберегти" → PR → прев'ю-посилання. "Опублікувати" → merge.

### 5. Пости для соцмереж
- Чернетки генеруються пайплайном (новий проєкт, реліз) і лежать у дашборді.
- Chrome-розширення показує чернетки в Side Panel на будь-якому сайті: копіювати, редагувати, позначити як опубліковане. Автовставка в редактор LinkedIn — пізніша версія.
- Публікацію завжди натискає сам користувач.

### 6. Чат-агент
Користувач описує зміну словами ("перепиши опис проєкту X коротше", "зроби темну тему"). Агент змінює дані портфоліо → PR з прев'ю.

### 7. Власний домен
Користувач додає домен, налаштовує CNAME, сервіс видає SSL і обслуговує сайт на ньому.

## Поза межами MVP
Автопостинг через API соцмереж, автовставка в редактори соцмереж, експорт на GitHub Pages, аналітика відвідувань, монетизація.
