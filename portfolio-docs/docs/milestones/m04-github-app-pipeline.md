# M4: Логін, GitHub App і автоматичний пайплайн

## Передумова
Ухвалені рішення з `architecture.md`, відкриті питання 2–4 → ADR.

## Обсяг
- `apps/app`: логін через GitHub, сесії, мінімальний дашборд (сайт, проєкти, задачі, налаштування `autoMerge`).
- GitHub App: встановлення, зберігання installation в D1, отримання installation token.
- Обробник вебхуків (Hono) з перевіркою підпису; виявлення подій за обраним механізмом (вебхуки та/або Cron).
- Черга: задача на подію; кроки пайплайну 1–8 з `architecture.md`; стан у `jobs`.
- PR у репо даних, коментар з прев'ю-посиланням, auto-merge за налаштуванням, продакшн-збірка після merge.
- Онбординг з `product.md` (флоу 1).

## Definition of done
- [ ] Новий користувач проходить онбординг і отримує опублікований сайт.
- [ ] Репо стає публічним з topic `portfolio` → PR з карткою і прев'ю без ручних дій.
- [ ] Зміна README → PR з оновленою карткою; поля з `editedFields` не змінені.
- [ ] Вебхук з невалідним підписом відхиляється до будь-якої обробки; тест.
- [ ] Повторна доставка однієї події не створює дубль PR; тест.
- [ ] Збій генерації чи збірки видно в дашборді з причиною; задачу можна перезапустити.
- [ ] `autoMerge: false` → PR чекає; `true` і всі перевірки зелені → merge і прод.
- [ ] Права GitHub App відповідають ADR — не ширші.
