# Learning notes

This is a learning project (see `CLAUDE.md`). After each milestone, write `docs/learning/mNN-<name>.md`, for example `m01-generator.md`. The notes are for the owner, so they explain rather than list.

## Every learning note contains

1. **What we built:** a short description of the result and how the parts connect, with a small diagram if the flow has more than three steps.
2. **Concepts:** each new technology, protocol or pattern used. For each one: what it is, what problem it solves here, and a link to primary documentation.
3. **Decisions:** every non-trivial choice made during the milestone. For each one: the options considered, what was chosen and why, and what would make us revisit it.
4. **How to verify it yourself:** commands to run and things to look at, so the owner can check the behaviour without help.
5. **Where to look in the code:** the key files and functions, in the order worth reading them.
6. **Questions to think about:** 2–3 questions that test understanding (for example, "what breaks if the webhook signature check is removed?"), with short answers at the end.

A decision that changes architecture also gets an ADR in `docs/adr/`; the learning note links to it.
